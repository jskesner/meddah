### 1.0 Module Registry, Capability Gating & Dormancy Architecture (`backend/app/ruleset_vm/module_registry.py`)

Meddah is a **universal ruleset interpreter**, not a game. Every subsystem in §1.2–§1.29 is therefore an **independent, optional module** that a user can enable, disable, or customize. The only non-optional code is the **Core** (Ruleset VM §1.1, event-sourced persistence, deterministic MUD parser, and the module registry itself). This section is the single source of truth for how modularity works; individual sections only describe *what a module does when active*.

#### 1. The `MeddahModule` Manifest
Every module ships a declarative manifest registered at startup:

| Field | Meaning |
| :--- | :--- |
| `module_id` | Stable identifier (e.g. `hit_locations`, `chase`, `law_justice`). |
| `spec_section` | The §1.x section that defines it. |
| `requires_primitives` | Ruleset building blocks the module needs in order to mean anything (e.g. `chase` needs a movement/contest resolution; `piety` needs a `HigherPowerBlock`). |
| `requires_modules` / `enhances_modules` | Hard dependencies vs. optional integrations (an `enhances` link degrades gracefully when the other module is off). |
| `provides` | Commands, UI panels, event hooks, schema blocks, and Studio editors the module contributes. All are hidden/unregistered when the module is not `active`. |
| `scope` | Where it can be toggled: `campaign`, `session`, or `player_local` (UI-only modules such as VFX or themes). |
| `ai_dependency` | Always `none` for core behaviour (Golden Rule #2); AI flair is a separate opt-in sub-toggle. |

#### 2. Three-State Resolution: `dormant` → `available` → `active`
1. **`dormant`**: The active ruleset supplies none of the module's `requires_primitives`. The module is **inert**: no commands, no UI, no prompts, no events, no AI context tokens, and zero CPU cost. *The engine never invents a mechanic to fill the gap* (Golden Rule #1 / Explicit Null Guarantee).
2. **`available`**: Required primitives exist but the host has not enabled the module. It appears only in the **Module Manager**.
3. **`active`**: Enabled by the Host/GM/Solo player (individually or through a *Module Profile*). Ruleset-declared primitives may *suggest* activation, but never force it.

> [!IMPORTANT]
> **Ruleset-defined ≠ engine-mandated.** If a ruleset defines a mechanic (hostile environments, crime, hit locations, piety, etc.), Meddah executes it faithfully *when the module is active*. A Host may still disable the module (an audited `MODULE_OVERRIDE` event records the choice so replay and rewind remain consistent). Nothing is ever "always on" except the Core.

#### 3. Disabling Is Graceful, Reversible, Permission-Gated & Disruption-Safe
* **Host-Controlled Module Toggling Permission (`can_toggle_campaign_modules`)**:
  - In Solo Play, the Solo Player is the Host and has full control over all module toggles.
  - In Multiplayer (Hosted Table or Persistent Guild Server), **Guest Players cannot toggle `campaign`- or `session`-scoped modules by default** (`can_toggle_campaign_modules: false` for `seat_role: player` and `spectator`; players may only adjust their own `player_local` client preferences such as local audio volume, local VFX/3D dice preferences within the Host's campaign visual policy, and accessibility settings).
  - The **Host (`is_server_admin / host`)** owns module-toggling authority and can selectively grant or revoke `can_toggle_campaign_modules` for **GM / Co-GM** seats.
* **Non-Disruptive Isolated Sandbox Test Instance (`[Test in Isolated Sandbox Instance]`)**:
  - To let the Host or authorized GM experiment with modules without disrupting an active multiplayer session, the **Module Manager** includes a **`[Test in Isolated Sandbox Instance]`** action that spins up a private, ephemeral Copy-on-Write clone of the current campaign snapshot in a local preview drawer (or pre-session staging window). The Host/GM can test-drive any module toggles or sub-options against sample rolls and encounters **with zero interruption or state mutation to the connected players in the live session**, and either discard the sandbox or stage the changes for the next safe boundary.
* **Safe-Boundary Live Activation & Automatic Checkpointing**:
  - Applying module changes to a live campaign requires an explicit Host/GM confirmation prompt (previewing any affected dependent modules), automatically writes a pre-change event-store checkpoint, and queues the audited `MODULE_OVERRIDE` event to activate at a **Safe Boundary**—defaulting to **`Next Scene / Rest / Session Boundary`** during an active multiplayer session (or **`End of Current Atomic Turn / Resolution Step`** when the Host/GM explicitly selects immediate turn-end activation), never aborting an in-flight dice roll or reaction window.
* **State is preserved, not deleted**: Module-owned state stays in the event log; disabling merely hides and freezes it, and re-enabling resumes it (replay hashes verify the round-trip). When toggling `hit_locations` or switching vitality topologies mid-campaign, current health percentages map proportionally between `vitality.total` and `vitality.locations[id]`.
* **Dependency validation**: Disabling a module with active dependents shows the exact fallback (e.g. turning off `hit_locations` makes armor revert to the ruleset's aggregate defense; turning off `law_justice` removes crime hooks but keeps settlements intact).
* **No orphaned UI**: Panels, Capabilities Deck tabs, action-bar buttons, Studio editors, and AI prompt fragments all unregister with their module.

#### 4. Module Profiles (Bundles of Toggles, Never Mechanics)
Profiles only flip module flags and sub-options; they contain no rules content:
* **Theater of the Mind / Minimal**: Core + AI/Deterministic GM + Capabilities Deck. Everything else off.
* **Classic Tabletop**: Minimal + tactical VTT, rest/downtime, loot, quests, companions.
* **Full Simulation**: Everything the ruleset has primitives for.
* **Custom**: Per-module checkboxes plus per-module sub-options. Users can save, share, and fork profiles (`.rpgprofile`), and apply them per campaign or per session.

#### 6. Modularity Rules for Authors of New Modules
1. A module **may not hardcode game terms, numbers, or outcomes**; values come from ruleset blocks or explicit user configuration (including defaults for *tone/pacing* settings, which are UX, not rules).
2. A module **may not import another module's internals**; it communicates through the Core event bus and declared `requires_modules`/`enhances_modules` (enforced by `import-linter` independence contracts, see the Development Workflow document).
3. Any "default" that changes *outcomes* (fudging, rescues, safety nets) must ship **off**, or be selected explicitly through a user-chosen profile or GM style preset.
4. Every module needs a **manifest**, a **dormancy test**, and an **on/off round-trip replay test** (Universal DoD item 8).

#### 7. Verification
* **Dormancy Conformance**: Loading `rules_light_narrative.rpgrules` (the zero-stat fixture) with *every* module installed must yield `dormant` for each module that needs absent primitives and expose only Core commands/UI.
* **Toggle Round-Trip**: For each module, `enable → play → disable → enable` yields an identical state hash to uninterrupted play.
* **`tools/lint_modularity.py`**: Fails CI if a module registers `provides` without a manifest, imports a sibling module, or contains a non-allowlisted game term.

### 1.1 Universal Ruleset VM (`backend/app/ruleset_vm/`)
0. **Universal Randomizer Primitives (`randomizers.py`)**:
   - Supports **7 deterministic randomizer kinds** bound cleanly to named seeded scene RNG streams (`rng.py`):
     1. `dice_formula` (`NdS` expressions with keep-highest `khK`, keep-lowest `klK`, exploding `!`, and arithmetic modifiers).
     2. `dice_pool` (`pool_size_formula` pools counting hits `>= success_threshold` with strict glitch ratio detection and optional `face_symbols`).
     3. `step_dice` (dynamic trait step-die sizes with optional exploding wild die and symbol mapping).
     4. `coin_flip` (single coin flip or multi-coin pools driven by `pool_size_formula`, customizable setting-agnostic face labels `coin_heads_label` / `coin_tails_label` such as *Sun/Moon* or *Crown/Skull*, `@roll.heads`/`@roll.tails`/`@roll.symbols` bindings, and direct linkage to the optional Phase 13 3D Metallic Coin-Flip tray in [Vol 4 §1.7.5](./tech_spec_04_multiplayer_ui_and_vtt.md)).
     5. `card_deck` (`table_shared` / `per_entity` / `encounter_local` draw without replacement + deterministic discard reshuffle).
     6. `resource_wager` (diceless resource/momentum bidding).
     7. `none` (pure narrative/deterministic resolution).
1. **Pluggable Flow & Turn Controller (`flow_controller.py`)**:
   - **`freeform` (Exploration / Social)**: Real-time/tick-based MUD flow; any entity can act at any time; background world clocks tick on scene changes or rest intervals.
   - **`round_initiative` (Structured Tactical)**: Entities roll the ruleset's `initiative_formula`; turns advance strictly down the sorted queue (with support for delayed turns, reactions per round, and start/end-of-turn ECA hooks).
   - **`popcorn_spotlight` (Narrative / PbtA / FitD)**: No fixed initiative order; the active actor or GM hands off the spotlight after each action, tracking action tokens so every participant gets spotlight opportunities.
2. **Contested Rolls & Explicit Reaction Windows (`reaction_window.py`)**:
   - When an action defines `allow_reactions: true` or `resolution_mode: "contested"`, the VM transitions the action into a `PENDING_REACTION` state.
   - It queries the target entity for valid Capabilities tagged with `trigger: "on_targeted"` (e.g., *Parry*, *Dodge*, *Counterspell*, *Spend Armor Slot*).
   - If the target is a **Human Player**, a glowing **Reaction / Contest Prompt** with a configurable timer appears on their screen (and they can pre-spending resources or pick a defense skill). If the target is an **AI Companion/NPC**, the deterministic tactical evaluator selects their optimal reaction immediately.
3. **Composable Container & Attachment Graph (`inventory_graph.py`)**:
   - Every item is an entity node that can contain child items (`capacity_rule`: weight sum, slot count, 2D grid, or abstract load limit) and can be mounted to named **Equip/Attachment Nodes** defined by the archetype (`main_hand`, `off_hand`, `neural_socket`, `spell_memory`, `backpack`).
   - **Universal Anatomical Slot Binding & Multi-Layer Apparel/Equipment Stacking (`anatomical_slots_and_layering_mode: "abstract_slots" | "anatomical_layered"`, Decoupled from Hit Locations & Armor-Only)**:
     - **Independent of Hit Locations & Combat**: Anatomical slot binding and layer stacking are first-class capabilities of `inventory_graph.py` that can be enabled in **any** ruleset—even when `hit_location_engine.enabled` is `false` (`vitality_topology: "monolithic"`) or in non-combat social/lifestyle RPGs.
     - **Applies to Clothing, Cosmetics, Disguises, Accessories, Gear & Armor (`WearableLayerSpec`)**: Any wearable item—not just armor—can bind to anatomical body locations (`head`, `face`, `neck`, `shoulders`, `torso`, `left_arm`, `right_arm`, `hands`, `waist`, `legs`, `feet`, or custom non-humanoid nodes) and declare multi-location coverage (`covered_locations: ["torso", "left_arm", "right_arm"]` for a silk tunic or chain hauberk; `["torso", "arms", "legs"]` for a tailored trenchcoat or ceremonial robe).
     - **Declarative Layer Ordering & Stacking Rules**: Rulesets (or optional user modules) define ordered wearable layers across each body location—for example: `1. base_undergarment / undersuit` $\rightarrow$ `2. inner_clothing (shirt, blouse, trousers)` $\rightarrow$ `3. mid_layer (vest, corset, padded gambeson)` $\rightarrow$ `4. protective_armor (cuirass, mail, plate)` $\rightarrow$ `5. outer_garment (cloak, greatcoat, tabard, ballgown, hazard suit)` $\rightarrow$ `6. accessory_and_cosmetic (jewelry, mask, hat, badge, or optional Cosmetic/Outfit Transmog Override layer)`.
     - **Cross-Subsystem Integration**:
       1. *Cosmetic & Paper-Doll Portrait/Token Compositing (§1.7.5)*: Renders the outermost visible clothing/cosmetic layers (or explicit cosmetic outfit overrides) on the character's paper-doll portrait and VTT token.
       2. *Social, Disguise, Dress-Code & Concealment Mechanics (§1.3 / §1.6 / §1.21)*: Outer garments project social and appearance tags (`#formal_court_attire`, `#faction_uniform_disguise`) and can conceal inner armor or holstered weapons worn on lower layers beneath a coat or cloak.
       3. *Climate & Environmental Protection (§1.14)*: Layered clothing and linings aggregate thermal/environmental protection tags (`cold_weather_furs`, `desert_breathable_linen`, `sealed_void_undersuit`) across covered body regions.
       4. *Combat Damage Mitigation & Prosthetic Sockets (§1.29)*: When protective armor layers are present, the engine evaluates layered mitigation and durability ablation (either globally or per struck hit location when `hit_locations` is active). When amputations are enabled, severed limbs expose an open **Prosthetic Socket** (and intact bodies can expose **Modular Augment Sockets**) where prosthetics or cybernetics mount as items.
       5. *Saved Outfit & Loadout Presets with Ruleset Don/Doff Timing*: Players can save named multi-layer **Outfit / Loadout Presets** (e.g., *Courtly Ballroom Attire*, *Arctic Expedition Layers*, *Full Combat Rig*) that swap in 1 click outside combat/during rest, while automatically enforcing the active ruleset's don/doff action or time costs if triggered during structured combat turns.
       6. *Diegetic Layer Concealment vs. Optional Host-Toggled Cosmetic Transmog (`cosmetic_transmog_enabled: false` by Default / RAW)*: Outer garments diegetically cover inner layers by default (updating paper-doll visuals and concealing inner armor/holstered weapons per ruleset perception/bulk rules, or remaining purely narrative if the ruleset has no concealment math). An optional non-diegetic **Cosmetic Transmog Override Slot** is disabled by default (Rules as Written) and can be opted into per campaign by the Host/GM.
   - Equipped/carried items project **Passive Modifier Auras** (e.g., `+2 @owner.armor`, `grant_action("shield_bash")`) that automatically recalculate derived formulas when equipped or dropped.
4. **State-Graph Character Creation & Advancement Engine (`advancement.py` & `desktop/src/components/character_builder/`)**:
   * **A. Mechanical Character Creation Engine (`creation_graph`)**:
     Every `.rpgrules` defines an ordered or branching state graph compiled from **5 agnostic step primitives** (auto-extracted by **Ingestion Probe #4** or edited visually in the Ruleset Studio):
     1. **Attribute & Stat Generation Nodes**:
        - `point_buy_pool`: Allocates $N$ budget points across properties using ruleset cost tables (non-linear costs, racial/background adjustments, min/max caps).
        - `array_assign`: Assigns fixed ruleset arrays (e.g., `[15, 14, 13, 12, 10, 8]`) to stats.
        - `random_roll_assign`: Executes ruleset dice formulas (e.g., `4d6kh3`, `3d6 * 5`), supporting both strict *Roll-in-Order* and *Roll-Pool-then-Assign* plus optional ruleset reroll/mercy thresholds.
     2. **Hierarchical Package, Archetype & Playbook Nodes (`package_pick`)**:
        - Supports any setting taxonomy (*Ancestry/Species $\rightarrow$ Culture/Background $\rightarrow$ Class/Subclass/Playbook $\rightarrow$ Talents/Spells/Cyberware*, or classless *Priority Tables A–E* & *Occupations*).
        - Enforces AST prerequisite gates (`requires: "@self.dex >= 13 && has_tag('martial')"`) and nested sub-choices (*"Pick 2 skills from `[Stealth, Sleight of Hand, Deception]`"*).
     3. **Procedural Lifepath & Career Chains (`lifepath_chain`)**:
        - Native state-machine loop for lifepath systems (*Traveller, Cyberpunk RED, Burning Wheel, MechWarrior*)—stepping through terms, survival/promotion checks, random life-event tables (allies, rivals, scars, windfalls), aging modifiers, and mustering-out benefits.
     4. **Starting Loadout, Currency & Compendium Shop (`starting_loadout`)**:
        - Supports fixed starting kits, rolled starting currency with an integrated **Starting Equipment Shop** (live capacity/weight/slot feedback), or abstract narrative load/kits.
     5. **Persona, Portrait, Voice & Covenant Binding (`identity_step`)**:
        - Name, pronouns, appearance, Portrait (upload, procedural SVG, or AI-generated), dedicated TTS voice profile, RP bonds/goals, and optional Deity/Patron `CovenantLink`.
   * **B. Mechanical Progression & Advancement Engine (`advancement_graph` — 5 Ruleset Paradigms)**:
     - **1. Tiered Level & Milestone Progression (`level_up_graph`)**: Triggered by `@self.xp >= xp_table[next_level]` or GM/Arc Milestones. Steps through class/archetype level nodes (HP roll vs. fixed average, scaling proficiencies, subclass selection, Ability Score Increase vs. Feat, spell learning, and ruleset-validated **Multiclassing** prerequisite checks).
     - **2. Classless XP / Karma Point-Buy Store (`xp_store`)**: Spend earned XP, Karma, or Legend Points directly on individual stats, skill ranks, edges, or perks using dynamic cost formulas (`cost: "next_rank * 5"`).
     - **3. Usage-Driven Skill Ticks & Roll-to-Improve (`skill_usage_ticks`)**: In BRP / *Call of Cthulhu* / *RuneQuest* style systems, `on_roll_resolved` ECA hooks automatically mark a skill with an `improvement_tick` when triggered (e.g., succeeding on a non-trivial check, or failing in *Dungeon World*). During Rest/Downtime/Session End, the VM executes the ruleset's **Improvement Roll Pass** (`1d100 > current_skill` $\rightarrow$ `+1d10`).
     - **4. Narrative Playbook XP Triggers & Clocks (`playbook_triggers`)**: Interactive end-of-session XP questionnaires (*PbtA / Forged in the Dark / Fate*) that advance playbook XP clocks and unlock new moves, clearances, or action dots.
     - **5. Diegetic In-World Training, Manuals & Augmentations (`diegetic_training`)**: Optional ruleset gates requiring an in-world Trainer NPC, Stronghold Training Hall/Cyber-Clinic, currency fee, or Downtime Project Clock to unlock a tier or technique.
   * **C. Character Creation & Progression GUI (`desktop/src/components/character_builder/`)**:
     - **Three Creation Modes (Switchable Any Time)**:
       1. **Step-by-Step Guided Wizard**: Dynamic breadcrumb stepper rendered straight from `creation_graph`, interactive point-buy/array/dice-tray widgets, searchable Compendium cards with automatic legal/ineligible prerequisite filtering, and a sticky **Live Derived-Stat Preview Sidebar** showing real-time recalculation (`HP`, `Defense`, `Initiative`, `Derived Pools`, `Load`) as choices change.
       2. **Conversational AI / Concept-Driven "Session Zero" Co-Creator (With Deterministic Keyword/Archetype Fallback)**: Type a plain-English concept (*"A paranoid ex-corporate medic with a rusty cyberarm"*); when an AI provider is active, it queries `.rpgrules` Compendium blocks to synthesize a **100% rules-legal character draft** and loads it straight into the Wizard. **When no AI provider is configured or available (`Tier A` / Failover)**, the **Deterministic Concept Keyword Matcher (`concept_archetype_matcher.py`)** tokenizes the prompt against **SQLite FTS5 BM25** compendium tags, archetypes, backgrounds, skills, and gear packages, then deterministically completes remaining `creation_graph` point-buy/array/loadout steps to produce a 100% rules-legal character draft offline.
       3. **Veteran Direct-Sheet / Fast-Track Mode**: Unlock free-form editing directly on the Dynamic Character Sheet (with toggleable ruleset legality badges), use **1-Click Random / Lifepath Roll**, or Import/Export JSON templates (reused by both Players, Solo Builders, and Human GMs rolling NPCs/Companions).
     - **In-Campaign Advancement Drawer & Before/After Stat Diff**:
       - When progression unlocks, a subtle **`[Advancement Available ✨]`** badge pulses on the Character Sheet header and HUD portrait.
       - Clicking opens a tailored **Advancement Drawer** matching the active ruleset paradigm (*Level-Up Stepper*, *XP Shopping Cart*, *Ticked-Skill Improvement Roller*, or *End-of-Session XP Checklist*), showing a **Before $\rightarrow$ After Stat Diff Summary** before committing an immutable `CHARACTER_ADVANCED` event to the Event-Sourced Campaign Store (reversible via checkpoints if needed).
     - **Portable Character Packages (`.rpgcharacter`) & Offline Sheet Export (`package_manager.py`)**:
       - **Portable `.rpgcharacter` Archive**: Any player or GM can export a character—including their current VM stats, `InventoryGraph` items, equipped outfit presets, paper-doll/portrait media assets, custom biography, and advancement history—into a signed, portable `.rpgcharacter` archive to transfer across campaigns, tables, or West Marches Guild Servers.
       - **Ruleset-Hash Compatibility & Host Approval Gate**: Importing a `.rpgcharacter` validates the character's `source_ruleset_hash` against the target campaign's active `.rpgrules` schema (flagging exact matches vs. compatible minor versions vs. missing properties/items requiring Host mapping). In Multiplayer and Guild Server modes, imported characters enter a **Host/GM Approval Queue** before joining the active roster, optionally stripping campaign-specific quest items or capping starting wealth/tier per table policy.
       - **Printable Offline Character Sheet Export (`Markdown / HTML / PDF`)**: One-click export of any character sheet into a clean, print-ready **Markdown, HTML, or PDF** layout reflecting the active ruleset's `SheetLayoutSpec` (`0` AI calls; uses pure-Python PDF fallback on headless servers).
5. **Built-In Showcase Rulesets (`sample_rulesets/showcase/`) & Conformance Fixtures (`sample_rulesets/conformance/`)**:
   To provide out-of-the-box Solo, Co-GM, and Multiplayer playability while proving zero-assumption engine agnosticism across radically different tabletop paradigms, the repository ships with **3 full playable Showcase Rulesets** and **4 minimal Conformance Fixtures**:

### 1.2 Ruleset Ingestion, Semantic Lifecycle Probes, JIT Compendium & Diff Workbench (`backend/app/ingestion/`)
1. **Hybrid Extraction Architecture (With 100% Deterministic Document Parser & Default FTS5 BM25 Retrieval)**:
   - **Core System Schema**: Attributes, derived formulas, randomizers, resolution mechanics, status conditions, and core actions are compiled directly into strict VM building blocks during ingestion.
   - **Indexed Compendium + JIT Compiler (SQLite FTS5 BM25 Default for `Tier A` & `Tier B`)**: Large reference catalogs (hundreds of spells, items, feats, monsters) are chunked and indexed into **SQLite FTS5 (`BM25` lexical search + structured entity/tag/rule-ID lookup)** as the **default engine across both `Tier A` and `Tier B`** (consuming `0` extra GPU VRAM and requiring no external embedding model alongside the 7–14B Ollama LLM), with optional local embeddings (e.g., `nomic-embed-text` / `ChromaDB`) available as an opt-in enhancement when VRAM allows. When a player or GM drags an item/spell/monster onto a sheet or scene, the **JIT Block Compiler** deterministically compiles that entry into a full VM Entity/Action block (and caches it in the ruleset). Users can also trigger a background batch-compile at any time.
   - **Deterministic Document Ingestor (`deterministic_ingestor.py`) & Deterministic-First `Tier B` Micro-Probe Pipeline**:
     - When no AI provider is configured (`Tier A`), PDF/Markdown/JSON/YAML/CSV rulebooks are ingested 100% deterministically using `PyMuPDF`/`pdfplumber` structural heading hierarchy parsers, Markdown/PDF table extractors, dice-notation (`\d+d\d+`) and stat-block regex grammars, and **SQLite FTS5 BM25** indexing—populating the exact same **Interactive Staging & Diff Review Workbench**.
     - When `Tier B` (7–14B Local LLM via Ollama) is active for unstructured rulebooks, the pipeline runs the **Deterministic Structural Parser FIRST** to extract structured tables directly and isolate relevant 1k–2k token text chunks per domain, then passes **only** those targeted chunks through **Domain-Specific `Tier B` Micro-Probes** using grammar-constrained JSON schemas (`format: <json_schema>`) with automatic per-probe checkpointing so long PDF runs stay strictly within the 4k–8k context window and can pause/resume at any time.
   - **URL Source Ingestion, Scoped Multi-Page SRD/Wiki Index Discovery & Polite Anti-DDoS Fetching (`backend/app/ingestion/url_ingestor.py`)**:
     - **Single-URL & Multi-Page Index Discovery (`--discover-links`)**: When a user supplies a URL pointing to an online SRD, wiki index, or documentation table-of-contents page, `url_ingestor.py` fetches **only** that single index page first (plus `robots.txt`), extracts outbound links strictly confined to the **same origin and URL path prefix** (e.g., `https://example-srd.org/rules/*`), deduplicates `#anchor` fragments, filters out non-content links (login/search/pagination/assets), and bounds discovery depth (`max_depth: 1` by default, configurable up to `2`).
     - **Interactive Sub-Page Checklist (`URLSubpageSelectorModal`)**: Never runs an uncontrolled background web crawler. Before fetching any linked child pages, the UI/CLI presents an interactive checklist of discovered sub-pages grouped by chapter/path (capped by a configurable `max_pages_per_job`, default: `25`). The user selects which chapters to ingest and clicks **`[Fetch & Stage Selected Pages]`**.
     - **Polite, Anti-Spam / Anti-DDoS Fetching Protocol (`PoliteFetchPolicy`)**:
       1. *Strict Single-Concurrency Queue (`max_concurrent_requests: 1`)*: Never sends parallel burst requests to a remote host; pages fetch sequentially one at a time.
       2. *Jittered Inter-Request Delay & `robots.txt` Compliance*: Enforces a polite delay between requests (`1.5s–3.0s` default with `±500ms` uniform random jitter), strictly honors `robots.txt` `Disallow` rules, `<meta name="robots">` directives, and any site-specified `Crawl-delay` if longer than the default delay.
       3. *SSRF & Resource Guards*: Validates DNS/IP on the initial request and every redirect hop (max 3 redirects) to block loopback, link-local, and private IPs; enforces a `15s` per-page timeout and `10MB` per-page size limit.
       4. *Conditional Caching & Pause/Resume (`ETag` / `Last-Modified`)*: Stores a content-addressed local snapshot of each fetched page with its `ETag` and `Last-Modified` headers so paused/resumed jobs or future SRD update checks use conditional `If-None-Match` requests (`304 Not Modified`) without re-downloading unchanged pages.
       5. *Rate-Limit Backoff & Graceful Human-in-the-Loop CAPTCHA / Challenge Recovery*: Honors HTTP `429` / `503` `Retry-After` headers with exponential backoff. If a remote host presents an anti-bot challenge, WAF gate, or CAPTCHA (e.g., Cloudflare Turnstile, hCaptcha, reCAPTCHA), **automated fetching immediately pauses in place** (the engine never attempts to solve, compute, click through, or bypass the challenge programmatically, and 100% of already-fetched pages remain safely saved in the `IngestionStagingJob`). Instead of failing the job, the Studio presents **3 Graceful Human-in-the-Loop Recovery Options**:
          - **Option A — Visible Human Verification Window (Electron Desktop App)**: Clicking **`[Complete Verification in Browser Window]`** opens a visible, interactive browser window to the gated URL so the **human user** can complete the verification challenge themselves directly in the UI. Once the user completes the challenge and the page loads, clicking **`[Capture Loaded Page & Resume Queue]`** ingests the user-verified page and resumes the remaining queue at a polite pace (or lets the user increase the inter-request delay to `5s–10s`).
          - **Option B — Inline Paste / Drag-and-Drop Sub-Page Slot (Desktop, Web Client & Headless Server)**: Every paused sub-page row in the job checklist exposes an **`[Open in External Browser]`** link alongside an inline **`[Paste Copied Text/HTML or Drop Saved File]`** slot. The user can open the page in their regular browser, copy the content or save the `.html`/`.md`/`.pdf` file, and paste/drop it directly into that paused row—preserving the page's exact URL citation, `#heading` anchors, and Table-of-Contents position within the multi-page job!
          - **Option C — Skip or Defer Individual Sub-Page**: The user can click **`[Skip This Page & Continue]`** to proceed with the already-staged pages and fill in the skipped chapter later.
     - **Unified Multi-Page Normalization & Anchor Citations**: Strips `<script>`, `<style>`, ads, navigation chrome, and hidden DOM elements in a sandboxed subprocess, merges all selected sub-pages into a single Table-of-Contents-ordered Structural Document AST for cross-page reference resolution, and preserves each block's exact sub-page URL and `#heading` anchor in `source_citation`.
2. **Active 14-Domain Semantic & Lifecycle Discovery Pass (`lifecycle_probes.py`)**:
   - **How the Engine Discovers Mechanics Without Assuming Them**: To bridge the gap between a 100% agnostic VM and every higher-level subsystem (from AI Companions knowing how to stabilize a fallen ally, to the VTT knowing how 2.5D elevation/cover works, to Capabilities Decks, Vehicles, Strongholds, Geopolitics, and Piety), the Ingestion Pipeline runs a comprehensive **14-Domain Semantic & Lifecycle Probe Pass** (using hybrid LLM+Vector retrieval when AI is enabled, or the **Deterministic 14-Domain Keyword, Heading & Regex Taxonomy Scanner** against SQLite FTS5 when AI is absent/unavailable).
   - Instead of assuming *"HP = 0 means Death Saves"* or *"Spell Slots exist"*, the extractor executes targeted semantic retrieval + structured extraction queries against the ingested rulebook chunks across **14 Universal Primitive Domains**:
     1. **Vitality, Incapacitation & Death Mechanics**: Searches for *vitality topology (monolithic vitality vs. independent hit locations vs. composite dual pools tracking both total vitality and individual limb health), tone constraints (narrative/light-hearted with amputations disabled vs. gritty/hardcore with permanent dismemberment), damage/harm thresholds, hit location tables, wounds, stress overflow, unconsciousness, bleeding out, death saves/checks, critical injury tables, instant death, or permanent mortality*. Compiles discovered rules into modular **`HitLocationTopologyBlock`** (`vitality_topology: "monolithic" | "independent_locations" | "composite_dual"`, `amputation_mechanics`, `medical_pipeline_mode`, `anatomical_slots_and_layering_mode`) + **ECA Event Hooks** tagged `lifecycle: "incapacitated" | "dying" | "dead"`.
     2. **Stabilization, Medical, Surgery & Resurrection / Restoration Mechanics**: Searches for *first aid, triage, stabilization checks, surgical operations, bone-setting, long-term recuperation, prosthetic/cybernetic installation, healing actions, resurrection spells/rituals, cybernetic trauma resuscitation, clone re-sleeving, fate/luck point death-defiance, or temple/clinic services* (including material costs, time windows, and permanent penalties like *Resurrection Sickness* or *Humanity/Essence Loss*). Tagged `semantic_role: "stabilize" | "revive" | "resurrect" | "surgery"` so AI Companions and Settlement Services discover and invoke them automatically.
     3. **Rest, Downtime & Resource Recovery**: Searches for *Short/Long Rests, Downtime actions, Vice/Recovery rolls, natural healing per day, Medbay/Inn stays, watch rotations, and ambush/disruption rules* (`rest_and_downtime` schema).

     5. **Tactical Spatial, Movement, Cover & 2.5D/3D Elevation Rules**: Searches for *grid type (square/hex/gridless), movement speed, diagonal metrics, terrain difficulties, cover modifiers, flanking, AoE shapes, line-of-sight, and tactical 2.5D/3D elevation/flight/falling/chasm rules* to populate `tactical_spatial_config`. Narrative rulesets using abstract "Zones" or "Theater of the Mind" compile `tactical_mode: "abstract_zones" | "theater_of_mind"` without forcing a tactical grid.
     6. **World Cosmology, Macro Scales (0–4), Z-Strata, Planar Topology & Megacities**: Actively searches for *macro map scales (star clusters/systems, continental/regional, hex), vertical world strata (`world_z_stratum`: orbit, sky/airships, surface, sewers, Underdark, abyssal), dimensional topologies (Independent Planes, Coterminous Mirror Realms like Feywild/Shadowfell/Umbra/Cyberspace, Transit Mediums like Hyperspace/Warp), megacity/district structural norms, and environmental traversal hazards (vacuum, radiation, pressure, planar portals)*. Compiles into modular **`Cosmology & Topology Building Blocks`**.
     7. **Social Contests, Morale, Sanity/Corruption & Reputation**: Searches for *social conflict mechanics, persuasion/intimidation/deception contests, sanity/terror/corruption/humanity tracks, NPC morale/rout checks, and faction reputation/standing scales*.
     8. **Capabilities, Spells, Stances, Reactions & Resource Pools (`Capabilities Deck`)**: Actively searches for *discrete player/NPC abilities across 4 categories (`action` attacks/maneuvers, `spell`/magic/psionic/program/force powers, `reaction` interrupts/parries/counters, and `stance`/passive toggles/auras)* along with *casting/activation times, concentration/sustain limits, verbal/somatic/material components, cooldowns, ammo/mana/ki/spell-slot resource pools, and ritual/upcasting rules*.
     9. **Retinue, Pets, Familiars, Mounts, Drones & Summons/Minions**: Searches for *animal companions, bonded familiars, mount riding/combat rules, autonomous drones/robots, temporary/permanent summons, mercenary hirelings, action-economy sharing rules (independent turn vs bonus-command vs mount control), and bond/loyalty traits*.
     10. **Pilotable Vehicles, Caravans, Naval/Starships & Setting/Tech Ontology**: Searches for *mounted wagons, siege engines, naval ships, airships, mechs, land vehicles, or starships* (crew stations, hull/shield/speed stats, boarding/chase rules, fuel/cargo, upgrade hardpoints) AND detects the rulebook's *Setting & Tech Ontology* (`tech_tier`, currency denominations, weapon/armor families, magical/psionic/cybernetic prevalence) so AI generation stays strictly canon-faithful.
     11. **Holdings, Strongholds, Bastions & Mass Warfare / Siege Rules**: Searches for *base/stronghold construction, bastions/headquarters, facility upkeep & income cycles, domain/realm management turns, unit/army scales, morale/routing, and siege warfare rules*.
     12. **Crafting, Alchemy, Traps, Survival, Encumbrance & Economy/Loot Tiers**: Searches for *item crafting/smithing/alchemy/enchanting/cyber-modding recipes and workstations, trap detection/disarm/trigger mechanics, survival meters (rations, water, foraging, exhaustion, temperature, encumbrance weight/slots/bulk), loot/treasure generation tables, and merchant barter/rarity economies*.
     13. **Overworld Travel, Multi-Floor Dungeons & Random Encounter/Event Tables**: Searches for *hex-crawl / point-to-point overland travel pace, forced march, navigation/getting-lost checks, weather hazards, watch orders, dungeon exploration turns (light/torches, wandering monster frequency), and native random encounter/event tables* (both combat & non-combat road/city/weather events).

   * **A. Categorized Drag-and-Drop Primitive & Pattern Palette (`PrimitivePalette.tsx`)**:
     - Organizes every universal building block into searchable, filterable categories:
       1. *Properties, Derived Stats & Resource Pools* (`Property`, `DerivedFormula`, `ResourcePool`, `ProgressClockBlock`)
       2. *Randomizers & Resolution Mechanics* (`DiceRandomizer`, `StepSymbolDice`, `DeckBlock`, `ResolutionMechanic`, `OutcomeTierTable`)
       3. *Time, Turn Flow & Reactions* (`FlowModeConfig`, `ActionEconomyBlock`, `ReactionWindow`, `ContestedRollSpec`)
       4. *Capabilities, Conditions & ECA Logic* (`CapabilityBlock`, `ConditionBlock`, `ConditionVisualSpec`, `ECA_EventHook`)
       5. *Inventory, Universal Apparel/Armor Layering & Anatomy* (`ContainerCapacityRule`, `AttachmentSlotNode`, `WearableLayerSpec`, `HitLocationTopologyBlock`)
       6. *Character Creation & Progression Graphs* (`CreationStepNode`: point-buy, array, roll, package, lifepath; `AdvancementParadigmBlock`)
       7. *Optional World & Gameplay Domain Blocks* (`LootTableBlock`, `EntityLootConfigBlock`, `HarvestableYieldBlock`, `CraftingRecipeBlock`, `RestAndDowntimeBlock`, `HigherPowerBlock`, `ChaseAndRaceConfigBlock`, `CompetitionBlueprintBlock`, `HubTopologyBlock`, `CosmologyAndStrataBlock`, `VehicleArchetypeBlock`, `HoldingArchetypeBlock`).
     - **Drag-and-Drop Wiring & No-Code Clause Builder**: Dragging an output port from a `Property` or `Randomizer` block into a `ResolutionMechanic`, `CapabilityBlock`, or `ECA_EventHook` automatically wires the reference (`@self.<prop_id>`) into the **Visual Formula & Condition Clause Builder** without typing syntax.
     - **1-Click Subsystem Pattern Macros**: Drag pre-wired multi-block templates (*"Stress & Trauma Track"*, *"Layered Armor + Durability Ablation"*, *"2d6 Tiered Action with Partial-Success Consequence"*, *"Usage-Driven Skill Tick Improvement"*) onto the canvas and customize their parameters visually.
   * **B. Interactive Dependency Graph Explorer & Live §1.0 Module-Readiness Inspector (`DependencyAndModuleGraph.tsx`)**:
     - **Upstream & Downstream Dependency Tracing**: Clicking any block switches or overlays the **Dependency Graph View**, highlighting every **Upstream Dependency** (properties, randomizers, or tags the block reads) and every **Downstream Consumer** (derived stats, actions, conditions, creation steps, or compendium entries that depend on it).
     - **Safe Refactoring & Rename Propagation**: Renaming any block or property ID (e.g., renaming `grit` $\rightarrow$ `resolve`) shows an instant impact preview and atomically updates every referencing AST formula, `ECA` trigger, and character sheet widget across the ruleset.
     - **Real-Time Validation & Cycle Highlighting**: Missing property links, type mismatches, unreachable `creation_graph` steps, or circular derived formulas (`Stat A <-> Stat B`) light up with red diagnostic badges on the canvas and a 1-click **`[Jump to Broken Link]`** inspector.
     - **Live §1.0 Module Registry Readiness Checklist**: Displays all optional engine modules (`hit_locations`, `anatomical_layering`, `chase`, `competition`, `piety_patrons`, `crafting`, `overworld_travel`, `west_marches_hubs`, etc.) and their current activation state (`dormant` vs. `available`) for the ruleset being edited—showing a clear checklist of which primitive blocks will unlock each module (e.g., *"Module `piety_patrons` is `dormant` — drag a `HigherPowerBlock` onto the canvas to unlock"*).
   * **C. Contextual Inline Documentation Hub & 7-Paradigm Example Cloner (`InlineDocsAndExamplesDrawer.tsx`)**:
     - **Context-Sensitive Field & Primitive Reference**: Clicking any block, input field, or AST operator updates the right-hand **Inline Documentation Drawer** (populated deterministically from schema docstrings and the Building-Block Reference Guide), displaying a clear summary, field-by-field descriptions, valid value ranges, and common usage tips.
     - **"How Other Rulesets Do This" Live Comparison Tab**: Every primitive's documentation card includes live, inspectable examples from the **7 bundled conformance rulesets** (`classic_d20_fantasy`, `grimdark_d100_investigative`, `narrative_2d6_clocks`, `dice_pool_successes`, `step_symbol_dice`, `resource_wager_card_draw`, `rules_light_narrative`) so designers can compare how d20 roll-over, d100 roll-under, 2d6 clocks, dice pools, step-dice, or card draws wire that exact same building block.
     - **1-Click `[Insert Example as Template]`**: Any example block from the 7 conformance rulesets (or the 3 showcase rulesets) can be cloned onto the user's canvas with one click and modified freely.
   * **D. Interactive Single-Block Test Bench & Live Probability Scratchpad (`RulesetTestScratchpad.tsx`)**:
     - Test any block, formula, or resolution mechanic in isolation without leaving the Studio: adjust mock `@self` and `@target` property sliders, click **`[Test Roll / Evaluate]`** to inspect the step-by-step deterministic AST trace and **`explain_ast_deterministically()`** plain-English breakdown, view the **Live Dice Probability Distribution Chart**, or run an instant `<500ms` **Monte Carlo TTK Sandbox** trial.
     - Includes bidirectional **Visual Nodes $\leftrightarrow$ Clean YAML/JSON Split View** so users who want to inspect or copy raw declarative schema definitions can toggle the synchronized code pane at any time.
   * **E. Integrated Drag-and-Drop Character Sheet & HUD Layout Designer (`SheetLayoutDesigner.tsx`)**:
     - Alongside mechanical building blocks, the Studio includes a visual **Sheet & HUD Layout Designer** tab where designers drag properties, derived stats, resource bars/clocks, paper-doll/hit-location silhouettes, layered equipment/apparel slots, and capability tabs onto a responsive grid canvas (with an automatic category-based layout fallback if a ruleset author skips custom layout design).
   * **F. Safe In-Campaign Ruleset Hot-Reloading & State Migration with Auto-Checkpoint (`ruleset_hot_reload.py`)**:
     - When a Host/GM or Solo Player tweaks a rule, adjusts a formula, or adds a homebrew block in the Studio while a campaign is already in progress, clicking **`[Hot-Reload / Apply to Active Campaign]`** automatically creates a pre-migration event-store checkpoint, validates state compatibility (prompting for default values on any newly added properties), commits an audited `RULESET_MIGRATED` event, and hot-reloads the active sheet and VM without requiring a new campaign.
