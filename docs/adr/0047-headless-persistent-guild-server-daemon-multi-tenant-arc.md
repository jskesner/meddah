# 0047. Headless Persistent Guild Server Daemon, Multi-Tenant Architecture & Zero-Trust Security Profile

- **Date**: 2026-11-23
- **Status**: Accepted
- **Deciders**: Maintainers, Architecture Design Session
- **Related Issues / Decisions**: Architectural Decision #47 (`docs/design/system_design_specification.md`)

## Context & Problem Statement
Architectural design constraint and domain resolution for **Headless Persistent Guild Server Daemon, Multi-Tenant Architecture & Zero-Trust Security Profile** in Meddah: The Universal Story Engine.

## Decision
**Dedicated Headless Server Mode (`meddah serve --mode guild-server` [Post-MVP Phase 14]) — Runs the Universal West Marches Campaign Paradigm**: While the West Marches paradigm can be used in any play mode (Solo, Co-Op, Hosted Table), it is the **only** campaign paradigm currently planned for `guild-server` mode and therefore provides dedicated multi-tenant server optimizations: **(1) Server-Authoritative Character Vault** (characters are created and stored on the server to prevent offline stat/item tampering; read-only PDF/sheet export allowed); **(2) Hybrid Account Authentication** (native self-hosted username/Argon2 + passkeys out-of-the-box with optional Admin Invite Codes, plus pluggable OAuth2 [Discord/OIDC] for community role sync and smurf prevention); **(3) Instance Supervisor & Concurrency Pooling** (manages server-configurable concurrent ephemeral expedition child branches [`max_concurrent_instances`, default: `10`], with configurable idle orphan reaping [`instance_idle_timeout_seconds`, default: `1800s` / 30m], and live SQLite WAL snapshots without disconnecting players); **(4) Deterministic Companion Architecture** (**Common Guild Hirelings** [public instance-local clones with standard tactical stances] vs. **Personal Retinue** [account-bound, settlement-phase relationship/deed reconciliation, zero in-dungeon mutiny], supporting 100% **Solo Expeditions with NPC Parties** with admin-configurable party size [`max_party_size`, default: `4`, range: `1..N`] and companion allowances [`max_companions_per_party`, default: `3`]); **(5) Deterministic Disconnect Handling** (configurable reconnect grace window [`reconnect_grace_seconds`, default: `600s` / 10m] $\rightarrow$ party vote to substitute from a roster of common NPC companions controlled 100% deterministically via the Zero-AI Ruleset VM [0 LLM compute] or safely extract to town); **(6) "Treasure Bundles & Merchant Unlock" Loot Mode (`loot_mode: "treasure_bundles"`)** (zero in-dungeon persistent gear drops; performance-based bounty bundles convert to ruleset-defined primary currency/wealth tokens and campaign guild renown marks at Atomic Settlement, while discovered items write to the party's `UnlockedMerchandiseRegistry` enabling all completing players to purchase/commission them at Hub Quartermasters); **(7) Multi-Scale Hub Services, Persistent Afflictions & Infinite/Tiered Merchant Stock** (operable across all Scale 0–4 Hub topologies; downtime services are strictly ruleset-defined, spawning only facilities defined in `.rpgrules` such as enchanting, tech repair, chronal paradox realignment, or trauma surgery with zero hardcoded genre assumptions; conditions tagged `persistent_condition_flag` do not auto-clear and require specialized temple/medical/chronal healing or player rituals; merchants have non-depleting base stock with per-PC unlock tiers based on quests, faction rep, and progression tier); **(8) Non-Aggression Safe Zones & Zoned PvP** (theft, pickpocketing, and PvP aggressive actions disabled by default in hubs; permitted only in designated `@spatial.pvp_enabled: true` arena/sparring nodes); **(9) Player Economy & Trading Safeguards** (`bind_on_pickup` tags for quest rewards, tier-gated trading, transaction audit logs); **(10) Multi-Guild, Multi-House & Multi-Faction Support** (independent faction reputations, exclusive quartermaster unlocks, and distinct Guild Halls); **(11) Dynamic 4-Axis Social & Diegetic Channel Creation** (`channel create` via GUI/MUD with scope, eligibility gates, OOC vs diegetic physics, and moderation policies) + prebuilt Guild Chat, Global OOC, Newbie/Help, and Hub LFG/Trade channels; **(12) Zero-Trust Hardened Security Profile (`ZeroTrustServerProfile`)** (all limits are server-admin configurable in `server.toml` with defaults: player audio broadcasts OFF by default, SVG paper-doll portraits default, parameterized SQL queries, HTML/URI escaping against XSS in MUD hypertext, AI prompt-injection bounding tags, `max_connections_per_ip: 3`, `rate_limit_per_second: 3`, `account_disk_quota_bytes: 2MB`); and **(13) Private Moderation Hierarchy** (Admin $\rightarrow$ Marshal $\rightarrow$ Guide $\rightarrow$ Player RBAC, `> mute`, `> detain/jail`, `> ban`, `> report` with configurable context capture lines [`report_context_lines`, default: `50`], private mod queue, instance-scoped X-Card).

## Consequences
### Positive
- Establishes an explicit, version-controlled architectural boundary aligned with Meddah's 4 Golden Rules.

### Negative / Trade-offs
- Requires strict adherence to schema validation, determinism, and modularity contracts during implementation.

### Neutral
- Recorded as part of the initial baseline architecture; revisions require a superseding ADR.
